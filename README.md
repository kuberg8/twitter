# Fullstack app

## Использование в режиме разработки

### Настройки `.env`

Пример настроек см. файл `.env.example`

Для ведения разработки создайте файл `.env` копированием из файла `.env.example` и отредактируйте его в соответствии с потребностями в папках frontend и backend.

### Запуск проигрывателя в режиме "горячей" перезагрузки изменений

```bash
docker compose up -d --build
```

```npm script
npm run dev:up
```

Приложения будут доступны по адресам

- frontend - `http://localhost:3001`
- backend - `http://localhost:3000`
## Фоновые push-уведомления

Подписка включается кнопкой **«Включить push-уведомления»** в чате отдельно на каждом устройстве. Пользователь разрешает уведомления в системном диалоге. На iPhone/iPad (iOS 16.4+) сначала добавьте сайт на главный экран через «Поделиться» → «На экран Домой» и откройте его с иконки.

Backend отправляет уведомления о новых сообщениях всем подписанным пользователям, кроме автора. Изменение и удаление сообщений не вызывают push. Подписки хранятся в MongoDB, не зависят от открытой вкладки или WebSocket. Выход из аккаунта отключает уведомления на устройстве; обработчик также проверяет получателя, чтобы не показывать push от предыдущего аккаунта.

### Настройка ключей

```bash
npm ci --prefix backend
npm run push:setup --prefix backend -- https://twitter-front-v3y5.onrender.com
```

Команда добавляет `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY` и `VAPID_SUBJECT` в локальный `backend/.env`, исключённый из Git. При повторном запуске существующая пара ключей сохраняется. Не генерируйте новую пару при каждом деплое: старые подписки связаны с исходным ключом.

### Публикация на Render

1. Опубликуйте изменения backend и frontend через существующий процесс деплоя.
2. В **backend-сервисе → Environment** добавьте три переменные из локального `backend/.env`: `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, `VAPID_SUBJECT`. Остальные существующие настройки оставьте на месте. Закрытый ключ не добавляйте во frontend и не коммитьте.
3. Пересоберите backend, чтобы установилась зависимость `web-push`, и frontend командой `npm run build`. Во frontend должны оставаться реальные HTTPS/WSS-адреса backend в `REACT_APP_API_URL` и `REACT_APP_WEBSOCKET_URL`, а не localhost.
4. Убедитесь, что `/push-sw.js` на frontend отдаётся как JavaScript, а не HTML fallback. Для Render Static Site можно добавить в Headers правило `/push-sw.js` → `Cache-Control: no-cache`. В приложенном Nginx конфиге оно уже есть.
5. Откройте обновлённый сайт, войдите и включите уведомления. На втором устройстве войдите **другим аккаунтом**, закройте чат на первом устройстве и отправьте сообщение со второго. Нажатие на уведомление должно открыть чат.

Если ключи не настроены, интерфейс прямо сообщает об этом. Истёкшие подписки (ответы провайдера 404/410) удаляются автоматически. Если ключи пришлось сменить, при следующем открытии чата старая подписка удаляется и уведомления нужно включить снова.

Звук системного push определяется настройками телефона; `sms.mp3` используется только открытой страницей. Доставка зависит от разрешений, сети и режима «Не беспокоить». Отправка выполняется после сохранения сообщения, без отдельной долговечной очереди: при перезапуске сервера во время отправки или временном сбое push-провайдера отдельное уведомление может быть потеряно, само сообщение остаётся в чате. На бесплатном Render после простоя backend может запускаться с задержкой.

Проверки:

```bash
npm test --prefix backend
CI=true npm test --prefix frontend -- --watchAll=false --runInBand --watchman=false
npm run build --prefix frontend
```

Документация: [Web Push для iOS](https://webkit.org/blog/13878/web-push-for-web-apps-on-ios-and-ipados/), [переменные Render](https://render.com/docs/configure-environment-variables), [ограничения бесплатного Render](https://render.com/docs/free).
